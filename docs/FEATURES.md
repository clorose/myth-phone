# MythPhone 기능 요구사항

이 문서는 MythPhone이 사용자에게 제공해야 하는 기능과 동작을 기록한다.
개발 방식과 작업 규칙은 루트의 `AGENTS.md`, 구조적 결정은 `DECISIONS.md`에서 관리한다.

## 현재 구현 상태

- 버블톡 1:1 대화는 실채팅이다. 친구 탭에 실제 Foundry 사용자가 표시되고, 메시지는 `ChatMessage` 귓속말(`whisper` + `flags.myth-phone`)로 저장·전달되며 재접속 후에도 유지된다.
- 참여자가 아닌 클라이언트는 해당 방과 메시지를 스토어에 반영하지 않고 폐기한다.
- 기본 메시지 앱은 연출용 JSON 데이터(`data/messages.json`)를 사용한다. 버블톡 더미 데이터는 제거되어 모든 버블톡 대화가 실채팅이다.
- 이메일 앱이 동작한다. 받은편지함과 상세 보기로 구성되며, 시나리오 메일은 `data/emails.json`에 연출용 데이터로 채운다. 본문에 이미지 첨부를 표시할 수 있다.
- 브라우저 앱이 동작한다. GM이 등록한 사이트(월드 설정 공유)를 목록에서 열거나 주소를 직접 입력하며, 페이지는 iframe으로 격리되어 표시된다. 사이트는 Foundry Data 폴더의 정적 HTML을 사용한다.
- 버블톡 UI는 친구, 1:1 채팅, 단체 대화의 세 섹션으로 분리되어 있다.
- 버블톡 목록과 대화 화면은 기본 메시지 앱과 독립된 렌더러를 사용한다.
- 버블톡 채팅방은 말풍선 꼬리(발화 그룹 첫 버블), 연속 메시지 묶음(아바타·이름 1회, 시간은 마지막만), 보낸 메시지 읽음 표시(1), 입력 중 표시, 배경 도트 패턴, 헤더 프로필(아바타·접속 점·통화 버튼)을 지원한다.
- 버블톡 목록은 구분선 없는 카드형 리스트다(선택 시 중립 카드 하이라이트, 기본 메시지 앱은 구분선 유지해 구분). 단체방 원형 모자이크 아바타, 알림 꺼짐 방 구분(bell-slash 아이콘과 회색 배지), 1:1 방 온라인 점, 채팅·단체 탭의 안읽음 합계 배지를 지원한다. 안읽음 방은 이름 볼드 + 배지로 표시한다. 아바타는 친구·대화방 모두 원형이다.
- 버블톡 채팅·단체 탭 상단에 전체/안읽음 필터가 있고, 대화가 일정 수(8개) 이상일 때만 날짜 구획(오늘/어제/지난 대화)이 켜진다. 목록 검색창은 없다.
- `muted`(알림 끔)와 `typing`(입력 중) 표시는 렌더러만 있고 실제 상태 연결은 아직 없다.
- 고정된 대화(핀) 기능은 아직 넣지 않는다. 도입 시 사용자별 클라이언트 설정으로 구현한다.
- NPC 개인톡이 동작한다. GM은 버블톡 우상단 가면 버튼에서 NPC Actor(플레이어 소유가 아닌 Actor만 표시)와 대상 플레이어를 골라 대화를 연다. 플레이어 화면에는 NPC 이름으로 표시되고, 답장은 GM 전원에게 귓속말로 돌아온다.
- 단체톡이 동작한다. 단체 대화 탭에서 방 이름과 참여자를 골라 만들고, 참여자 전원에게 귓속말로 전달된다.
- 안읽음·읽음 표시가 동작한다. 방 목록·탭·홈 아이콘에 안읽음 배지가 표시되고 방을 열면 사라진다. 보낸 메시지 옆 숫자는 아직 읽지 않은 상대 수이며 상대가 읽으면 실시간으로 사라진다. 방이 닫혀 있을 때 새 메시지가 오면 알림음과 토스트가 표시된다.
- 통화 기록은 사용자별로 유저 플래그에 저장되어 재접속 후에도 유지된다(최근 50건).
- 연락처가 실제 데이터와 연결된다. 사용자 목록과 NPC 연락처(Actor 플래그의 번호)를 표시하고, GM은 추가·수정·삭제할 수 있으며, 메시지 버튼으로 해당 대화방이 바로 열린다.
- 버블톡에서 이미지 첨부가 동작한다. 파일 탐색 권한이 있는 사용자가 + 버튼으로 이미지를 골라 보내면 말풍선에 표시되고, 누르면 크게 볼 수 있다. 로그 내보내기에는 [사진: 경로]로 표기된다.

## 사용자 식별

- 실제 기능에서 사용자를 구분할 때 표시 이름이 아니라 Foundry 사용자 ID를 사용한다.
- 표시 이름은 화면 출력에만 사용한다.
- 폰 화면에서 유저는 계정 이름이 아니라 배정된 캐릭터 이름으로 표시한다(미배정이면 계정 이름). 폰은 세계관 안 물건이므로 UI 문구에서도 "NPC" 대신 "캐릭터"라고 지칭한다.
- 전화번호, 연락처, 채팅방 참여 정보는 Foundry 사용자 ID와 연결한다.

## 전화

### 목적

전화는 스마트폰 분위기를 구성하는 기본 앱으로 유지한다.
버블톡처럼 지속적인 대화를 담당하지 않고, GM이 NPC 명의로 특정 플레이어에게 짧고 긴급한 내레이션을 전달하는 연출 기능으로 사용한다.

대표적인 사용 예:

```text
"지금 거기서 당장 나와!"
→ 상대가 즉시 전화를 끊음
```

전화에서 장시간 양방향 대화, 분기 선택지, 실제 플레이어 간 음성 연결은 우선 구현 범위에 포함하지 않는다.

### 개인 수신

- GM은 전화받을 플레이어를 한 명 이상 지정할 수 있다.
- 벨소리, 진동, 수신 화면, NPC 대사와 상황 연출은 지정된 플레이어에게만 표시한다.
- 대상이 아닌 플레이어에게는 전화가 왔다는 사실도 기본적으로 노출하지 않는다.
- GM 화면에는 발신과 진행을 위한 제어 상태만 표시하고 벨소리는 재생하지 않는다.
- 통화 이벤트를 받은 클라이언트는 `targetUserId` 또는 대상 ID 목록에 현재 사용자 ID가 있는지 확인한 뒤 처리한다.

### GM 발신과 대상 지정

- 현재 구현된 테스트 전화는 버튼을 누른 사용자의 브라우저에서만 실행되는 로컬 UI 테스트다.
- 실제 발신 기능은 GM 전용 화면에서 제공한다.
- GM은 발신 NPC Actor, 수신 플레이어, 실행할 전화 장면을 선택한 뒤 전화를 건다.
- 발신 NPC의 이름과 이미지는 Foundry Actor에서 가져온다.
- NPC 전화번호는 해당 Actor의 `myth-phone` 플래그에 저장할 수 있다.
- 수신자 목록에는 사용자 이름을 표시하지만 실제 대상 식별에는 Foundry `User.id`를 사용한다.

GM 발신 이벤트 예시:

```js
game.socket.emit("module.myth-phone", {
  type: "incomingCall",
  senderUserId: game.user.id,
  targetUserId: selectedUser.id,
  caller: {
    actorUuid: npcActor.uuid,
    name: npcActor.name,
    image: npcActor.img,
    number: npcActor.getFlag("myth-phone", "phoneNumber")
  },
  sceneId: "hacker-ambush"
});
```

각 클라이언트는 전화 이벤트의 `targetUserId`가 현재 `game.user.id`와 일치할 때만 벨소리와 수신 화면을 실행한다.

```js
game.socket.on("module.myth-phone", (payload) => {
  if (payload.type !== "incomingCall") return;
  if (payload.targetUserId !== game.user.id) return;

  SmartphoneShell.receiveIncomingCall(payload);
});
```

- A를 대상으로 한 전화는 A에게만 표시하고 B와 C는 아무것도 표시하거나 재생하지 않는다.
- 플레이어가 응답하거나 거절하면 결과를 GM에게 소켓 이벤트로 돌려보낸다.
- 응답한 플레이어의 클라이언트에서 `sceneId`에 해당하는 전화 연출을 실행한다.
- GM에게는 발신 중, 응답, 거절, 종료 상태를 표시하되 대상 플레이어의 벨소리는 재생하지 않는다.

### 통화 흐름

1. GM이 발신 NPC와 수신 플레이어를 선택한다.
2. 대상 플레이어에게만 벨소리와 수신 화면을 표시한다.
3. 플레이어는 응답하거나 거절한다.
4. 응답하면 GM이 준비한 짧은 NPC 대사를 표시한다.
5. 대사가 끝나면 NPC가 전화를 끊고 통화를 자동 종료한다.
6. 최근 통화 또는 부재중 전화 기록을 남긴다.

### 통화 내용 표시

- 현재 NPC 대사는 통화 화면의 자막 형태로 크게 표시한다.
- 전화는 한두 문장의 짧은 내레이션을 기본으로 한다.
- GM은 발신 전에 NPC 대사와 통화 종료 시점을 준비한다.
- 플레이어 선택지나 대화 분기 엔진은 만들지 않는다.
- 상세 대화 기록은 기본적으로 남기지 않고 발신자, 시각, 수신·부재중 여부만 최근 통화에 기록한다.

### 전화 장면 데이터

- 모듈에 포함된 기본 전화 장면은 `data/call-scenes.json`에 JSON으로 저장한다.
- 각 장면은 고유 ID, 표시 이름, 발신자 정보와 시간순 `beats` 배열을 가진다.
- 장면 요소의 `type`은 `dialogue`, `stage`, `end`를 사용한다.
- `delay`는 통화 응답 시점부터 해당 요소를 실행할 때까지의 밀리초다.
- `effect`는 모듈에 등록된 문 두드림, 충격, 발소리, 종료음 등의 효과를 지정한다.
- 테스트 전화는 `hacker-ambush` 장면을 JSON에서 불러와 실행한다.
- 향후 GM이 작성한 장면은 동일한 JSON 구조를 JournalEntry 플래그에 저장한다.

### 개인 설정

- 벨소리 켜기와 끄기
- 벨소리 음량
- 진동만 사용
- 전화 미리보기
- 수신 화면 자동 표시
- 방해 금지 모드

## 버블톡

### 메시지 앱과의 구분

- `메시지`는 전화번호 기반 기본 문자 앱이다.
- `버블톡`은 친구와 채팅방 기반의 별도 모바일 메신저다.
- 두 앱은 홈 화면과 데이터 구조에서 서로 독립적으로 유지한다.

### 개인톡

- 개인톡 채팅방은 참여한 사용자에게만 목록과 내용을 표시한다.
- A와 B의 개인톡은 A와 B만 확인할 수 있다.
- 참여하지 않은 C에게는 채팅방, 메시지, 알림과 소리를 노출하지 않는다.
- 메시지 전송과 알림은 참여자의 Foundry 사용자 ID를 대상으로 한다.

예시 데이터:

```js
{
  roomId: "room-001",
  type: "direct",
  participantUserIds: ["player-a", "player-b"],
  messages: []
}
```

### 단체톡

- 단체톡은 `participantUserIds`에 포함된 모든 사용자에게 표시한다.
- 참여하지 않은 사용자에게는 채팅방 자체를 표시하지 않는다.
- 초대, 나가기, 방 이름과 참여자 목록 변경을 이후 확장 기능으로 고려한다.

예시 데이터:

```js
{
  roomId: "party-chat",
  type: "group",
  participantUserIds: ["player-a", "player-b", "player-c"],
  messages: []
}
```

### NPC 대화

- NPC는 Foundry `Actor` 또는 씬의 `TokenDocument`를 버블톡 연락처와 대화 상대로 사용한다.
- GM은 자신이 운용하는 Actor 또는 Token을 화자로 선택해 메시지를 발송한다.
- Foundry `ChatMessage.speaker`에는 `ChatMessage.getSpeaker({ actor, token, alias })`로 생성한 화자 정보를 저장한다.
- 버블톡은 `speaker.actor` 또는 `speaker.token`을 이용해 NPC 이름과 이미지를 표시한다.
- 동일한 Actor라도 씬의 특정 Token을 선택한 경우에는 해당 Token 화자 정보를 우선할 수 있다.
- NPC 메시지의 실제 작성자는 GM이지만 버블톡과 Foundry 채팅에는 선택한 Actor 또는 Token이 화자로 표시된다.
- 대화방 플래그에는 상대 Actor UUID와 필요하면 Token UUID를 저장해 GM이 여러 NPC를 구분해 운용할 수 있게 한다.
- NPC 개인 메시지도 해당 채팅방 참여자에게만 표시한다.

### 알림과 기록

- 새 메시지 알림과 소리는 채팅방 참여자에게만 전달한다.
- 읽지 않은 메시지는 사용자별로 관리한다.
- 보낸 메시지 옆의 읽음 표시 `1`은 상대가 그 메시지를 읽으면 사라진다. 단체톡에서는 아직 읽지 않은 참여자 수를 표시하고 모두 읽으면 사라진다.
- 채팅방의 안읽음 배지(방 목록·탭 합계)는 사용자가 그 방을 열어 읽는 순간 사라진다. 사용자별 마지막 읽은 시각을 기준으로 계산한다.
- 대화 기록은 새로고침과 재접속 후에도 유지해야 한다.
- 완성형 버블톡 메시지는 Foundry `ChatMessage` 귓속말로 생성해 실시간 전달과 기록에 사용한다.
- `whisper`에는 개인톡 또는 단체톡 참여자의 Foundry 사용자 ID를 넣는다.
- `flags.myth-phone`에는 `app`, `roomId`와 NPC Actor/Token 식별 정보를 저장해 버블톡 대화방으로 분류한다.
- GM이 NPC로 보낸 메시지는 선택한 Actor/Token을 `ChatMessage.speaker`로 사용한다.
- 플레이어가 NPC 대화방에서 보낸 답장은 GM을 귓속말 수신자로 지정하고 같은 `roomId`에 연결한다.
- Foundry 기본 채팅 로그에서 귓속말이 함께 보이는 동작은 실제 구현 단계에서 확인하고, 필요하면 MythPhone 메시지만 구분해 표시 방식을 조정한다.

## 개인정보 표시 원칙

- UI에서 보이지 않게 하는 것뿐 아니라, 대상이 아닌 클라이언트에는 가능한 한 민감한 대화 내용을 전달하지 않는 구조를 목표로 한다.
- 불가피하게 모듈 소켓이 모든 클라이언트에 이벤트를 전달하면 수신 즉시 대상 사용자 ID를 검사하고 무관한 이벤트를 폐기한다.
- 채팅방 목록, 메시지 본문, 알림 미리보기와 통화 대사는 모두 같은 참여자 검사를 적용한다.

## 이미지와 증거 자료

### 기본 표시 방식

- 메신저, 버블톡 또는 이메일로 받은 이미지는 해당 메시지의 첨부 파일로 직접 표시한다.
- 플레이어는 이미지를 확인하기 위해 별도의 사진 앱으로 이동하거나 먼저 저장할 필요가 없다.
- 증거 이미지는 이미지 자체뿐 아니라 발신자, 설명, 전후 대화와 수신 시각이 의미를 결정하므로 원본 대화 문맥을 우선 보존한다.
- 비슷한 증거 사진이 여러 장일 때 출처 정보 없이 이미지만 한곳에 모으면 각각의 의미를 구분하기 어려우므로 독립적인 사진 앱은 현재 개발 대상에 포함하지 않는다.

예시:

```text
지아:
"세 번째 창문만 불이 켜져 있어.
이 사진 확대해서 봐."

[증거 사진]
```

### 향후 통합 보관 기능

- 여러 앱의 증거를 모아야 할 필요가 생기면 일반 사진 앱보다 `증거 보관함` 형태를 우선 검토한다.
- 증거 보관함에 자료를 저장할 경우 다음 문맥 정보를 이미지와 함께 유지해야 한다.
  - 발신자
  - 수신 시각
  - 원본 메시지 또는 설명
  - 출처 앱과 대화방
  - 원본 대화로 돌아가는 링크
- 카메라 앱은 구체적인 촬영 대상과 게임 내 사용 목적이 정해지기 전까지 개발하지 않는다.
