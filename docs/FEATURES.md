# MythPhone 기능 요구사항

MythPhone이 사용자에게 제공해야 하는 동작과 개발 범위를 기록한다. 현재 구현 여부는 실제 코드,
결정 이유는 `DECISIONS.md`, 사용법은 `GUIDE.md`에서 확인한다.

## 핵심 원칙

- 폰 화면에서 사용자는 계정명이 아니라 배정된 캐릭터 이름으로 표시한다. 미배정이면 계정명을 쓴다.
- 내부 식별에는 표시 이름이 아닌 Foundry 문서 ID를 사용한다.
- 버블톡은 실제 채팅, 기본 메시지·이메일은 GM이 준비하는 연출 데이터다.
- 실시간 전달과 영구 저장을 분리한다.
- 대상이 아닌 사용자에게 개인 대화·전화·알림을 노출하지 않는다.
- 이미지 단서는 발신자·설명·수신 시각이 보이는 원본 대화 문맥에서 먼저 제공한다.

## 전화

### 역할

전화는 플레이어끼리의 음성 통화가 아니라 GM이 긴급한 NPC 내레이션을 전달하는 연출 기능이다.
장시간 양방향 대화, 분기 대화 엔진, 실제 음성 연결은 범위에 포함하지 않는다.

### 발신과 수신

- GM은 수신 플레이어 한 명과 전화 장면 하나를 선택해 발신한다.
- 발신자 이름·이니셜·번호는 Actor가 아니라 선택한 전화 장면이 소유한다.
- 대상 플레이어에게만 벨소리와 수신 화면을 표시한다.
- 응답하면 장면의 대사·지문·효과음을 시간순으로 재생하고 장면이 종료되면 통화를 끝낸다.
- 거절·응답 결과는 GM에게 알린다. 플레이어가 통화 도중 직접 끊는 동작은 GM에게 보고하지 않는다.
- 통화 기록에는 발신자, 번호, 시각, 수신·거절 결과를 남기며 사용자별로 저장한다.
- 전화 장면은 `data/call-scenes.json`에 저장한다. 작성 형식은 `GUIDE.md`를 따른다.

### 향후 후보

실제 필요가 확인되면 벨소리 음량, 진동, 수신 화면 자동 표시 같은 개인 설정을 별도로 검토한다.
현재 요구사항은 아니다.

## 버블톡

### 개인톡

- 친구 목록은 실제 Foundry 사용자를 표시한다.
- 1:1 방은 두 사용자 ID로 결정하며 참여자만 목록·본문·알림을 볼 수 있다.
- 메시지는 `ChatMessage` 귓속말로 저장·전달되어 재접속 후에도 유지된다.
- 방을 열면 사용자별 마지막 읽은 시각을 갱신한다.
- 보낸 메시지 옆 숫자는 아직 읽지 않은 상대 수를 뜻하며 상대가 읽으면 갱신된다.

### 캐릭터 명의 대화

- GM은 플레이어 소유가 아닌 Actor와 대상 플레이어를 골라 캐릭터 명의 대화를 연다.
- 플레이어에게는 GM 계정명이 아니라 선택한 Actor 이름과 초상화를 표시한다.
- 플레이어 답장은 GM에게 전달되어 같은 방에 연결된다.
- 현재 화자 구현은 Actor 기준이다. 특정 Token 화자 지원은 현재 범위가 아니다.

### 단체톡

- 사용자는 방 이름과 참여자를 골라 단체방을 만든다.
- 참여자 전원에게 메시지를 전달하고 미참여자에게는 방을 표시하지 않는다.
- 방 메타데이터는 단체 메시지 플래그에 포함해 재접속 시 복원한다.
- 목록 아바타는 참여자 초상화 모자이크로 표시한다.
- 초대·나가기·방 정보 변경은 다음 개발 후보로 둔다.

### 알림과 첨부

- 방이 닫힌 상태에서 받은 메시지는 사용자 설정에 따라 토스트·소리·미리보기를 표시한다.
- 방·탭·홈 아이콘에 안읽음 수를 표시한다.
- 파일 탐색 권한이 있는 사용자는 이미지와 선택적인 캡션을 보낼 수 있다.
- 이미지는 말풍선에서 표시하고 클릭하면 확대한다.
- 현재 실시간 버블톡 말풍선에는 시각을 표시하지 않는다. timestamp는 정렬과 읽음 계산에 사용한다.

## 연출 메시지·이메일

- 연출 데이터의 영구 정본은 `myth-phone.messages`와 `myth-phone.emails` world 설정이다.
- 번들 JSON은 새 월드 최초 1회 시드에만 사용한다.
- GM은 Scene Controls의 `GM툴` 독립 창에서 메시지·이메일·게임 날짜를 편집한다.
- 새 항목은 기본적으로 미발송이며 GM은 항상 미리 볼 수 있다.
- GM은 발송할 때 받을 플레이어들을 선택한다. 여러 명에게 보내도 각자에게 온 개인 연출로 취급한다.
- 대상 추가 시 신규 대상에게만 도착 알림을 보내고, 대상 해제 시 해당 플레이어에게서 회수한다.
- 연출 메시지는 말풍선마다 월·일과 선택 시각을 갖는다.
- 날짜가 바뀌는 지점에는 구분선을 넣고 같은 방향·같은 시각의 연속 말풍선은 마지막에만 시각을 표시한다.
- 이메일은 발신자·주소·제목·수신 시점·본문을 가진다.
- 메시지·이메일을 열면 사용자별 연출 읽음 상태를 저장한다.
- JSON 가져오기·내보내기로 월드 데이터를 백업하거나 이관할 수 있다.

## 게임 날짜와 달력

- GM은 `GM툴`에서 게임 내 연·월·일을 설정하거나 현실 날짜로 초기화한다.
- 게임 날짜는 폰 날짜 줄, 연출 시점 라벨, 달력의 기준 날짜로 사용한다.
- 달력은 월 이동, 오늘 복귀, 날짜 선택, 양력 공휴일 표시를 제공한다.
- 개인 일정은 User 플래그에 저장하며 작성자 본인에게만 보인다.
- 공개 일정은 현재 범위가 아니다.

## 연락처

- 실제 Foundry 사용자와 연락처 플래그가 있는 Actor를 표시한다.
- GM은 Actor 연락처와 전화번호를 추가·수정·삭제한다.
- 플레이어는 연락처에서 해당 사용자 또는 Actor와 버블톡을 시작할 수 있다.
- 현재 Actor 연락처는 모든 사용자에게 보인다.

## 브라우저

- GM이 world 설정에 등록한 사이트 목록을 모든 사용자가 공유한다.
- Foundry Data 폴더의 정적 HTML을 iframe으로 열어 페이지 CSS·JS를 폰과 Foundry UI에서 격리한다.
- 주소창으로 Data 경로를 직접 열 수 있다.
- 자주 쓰는 페이지 유형의 제작 템플릿은 다음 개발 후보로 둔다.

## 로그 내보내기와 개인정보

- 사용자는 자신이 참여한 버블톡 방을 텍스트로 내보낼 수 있다.
- GM 통합 로그는 기본 채팅과 캐릭터↔플레이어 방을 포함한다.
- 단체방은 GM이 옵션을 켠 경우에만 통합 로그에 포함한다.
- 사용자 간 1:1 버블톡은 당사자가 직접 내보내 제공하지 않는 한 GM에게 노출하지 않는다.
- 이미지 메시지는 내보내기에서 파일 경로를 함께 기록한다.

## 다음 개발 후보

1. 캐릭터 연락처 노출 범위 — 사용자가 아는 캐릭터만 표시
2. 단체톡 초대·나가기
3. 브라우저 페이지 제작 템플릿
4. 디자인 토큰 정리 후 폰 스킨 시스템
5. 출시 전 `scripts/log.js`의 `DEBUG = false`

## 결정 대기

- GM툴 상세 편집 화면에도 큰 발송 버튼을 추가할지
- 버블톡 입력 중 상태를 실제 소켓 이벤트와 연결할지
- 방 알림 끄기 기능을 구현할지
- 동작 없는 채팅방 헤더 통화 버튼을 유지할지
- 녹음기·음성 메모 앱을 만들지
- Foundry 사이드바에서 MythPhone 대화를 별도로 구분할지
- 참여자가 대화를 기본 채팅에 공개하는 공유 기능을 만들지

## 보류

- 카메라 앱 — 촬영 대상과 플레이 목적이 정해지기 전까지 개발하지 않는다.
- 잠금화면 — 현재는 해제 단계가 마찰만 추가하므로 만들지 않는다.
- 독립 사진 갤러리 — 필요하면 문맥을 보존하는 증거 보관함으로 다시 검토한다.
- 고정된 대화 — 도입 시 사용자별 설정으로 구현한다.
- GM 작성 전화 장면의 JournalEntry 저장 — 파일 기반 장면으로 부족할 때 검토한다.
